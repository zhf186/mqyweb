# 需求文档 - 可视化页面编辑器

## 简介

为CMS后台管理系统添加可视化页面编辑功能，让管理员能够在实际页面预览中直接点击和编辑内容，提供所见即所得的编辑体验。

## 术语表

- **Visual_Editor**: 可视化编辑器，允许用户在页面预览中直接编辑内容
- **Preview_Mode**: 预览模式，显示实际网页的iframe预览
- **Edit_Mode**: 编辑模式，在预览页面上可以点击元素进行编辑
- **Content_Overlay**: 内容覆盖层，在可编辑元素上显示的编辑提示
- **Inline_Editor**: 内联编辑器，在页面上直接编辑文字或图片的弹窗
- **CMS_Backend**: CMS后台管理系统
- **Frontend_Page**: 前端实际页面

## 需求

### 需求 1：预览按钮和预览模式

**用户故事**：作为内容管理员，我想点击"预览"按钮查看实际页面效果，以便了解内容在网站上的真实显示。

#### 验收标准

1. WHEN 用户在内容管理页面点击"预览"按钮 THEN 系统应打开预览模式显示实际页面
2. WHEN 预览模式打开 THEN 系统应在iframe中加载对应的前端页面
3. WHEN 预览页面加载完成 THEN 系统应显示"进入编辑模式"按钮
4. WHEN 用户点击"关闭预览" THEN 系统应返回内容管理列表页面

### 需求 2：可视化编辑模式

**用户故事**：作为内容管理员，我想在预览页面上直接点击内容进行编辑，以便直观地修改网页内容。

#### 验收标准

1. WHEN 用户点击"进入编辑模式"按钮 THEN 系统应在所有可编辑元素上显示编辑提示
2. WHEN 鼠标悬停在可编辑元素上 THEN 系统应高亮显示该元素并显示编辑图标
3. WHEN 用户点击可编辑的文字元素 THEN 系统应打开文字编辑弹窗
4. WHEN 用户点击可编辑的图片元素 THEN 系统应打开图片编辑弹窗
5. WHEN 用户在编辑模式下点击"退出编辑模式" THEN 系统应隐藏所有编辑提示恢复预览模式

### 需求 3：文字内联编辑

**用户故事**：作为内容管理员，我想在预览页面上直接编辑文字内容，以便快速修改文案。

#### 验收标准

1. WHEN 用户点击文字元素 THEN 系统应显示文字编辑弹窗包含当前内容
2. WHEN 文字编辑弹窗打开 THEN 系统应显示中文和英文两个输入框
3. WHEN 用户修改文字内容并点击"保存" THEN 系统应更新数据库并刷新预览页面
4. WHEN 用户点击"取消" THEN 系统应关闭弹窗不保存修改
5. WHEN 保存成功 THEN 系统应显示成功提示并在预览页面实时更新内容

### 需求 4：图片内联编辑

**用户故事**：作为内容管理员，我想在预览页面上直接替换图片，以便快速更新页面视觉内容。

#### 验收标准

1. WHEN 用户点击图片元素 THEN 系统应显示图片编辑弹窗包含当前图片预览
2. WHEN 图片编辑弹窗打开 THEN 系统应显示当前图片路径输入框
3. WHEN 用户修改图片路径并点击"保存" THEN 系统应更新数据库并刷新预览页面
4. WHEN 用户输入新图片路径 THEN 系统应实时预览新图片
5. WHEN 保存成功 THEN 系统应在预览页面显示新图片

### 需求 4.1：图片选择器（增强）

**用户故事**：作为内容管理员，我想从图片库中选择图片进行替换，而不是手动输入路径，以便更方便地管理图片。

#### 验收标准

1. WHEN 图片编辑弹窗打开 THEN 系统应显示该页面所有可用图片的缩略图网格
2. WHEN 显示图片网格 THEN 系统应根据当前页面分类筛选图片（如首页、ebike等）
3. WHEN 用户点击某张图片缩略图 THEN 系统应选中该图片并显示预览
4. WHEN 用户选择新图片 THEN 系统应自动填充图片路径到输入框
5. WHEN 用户保存选择的图片 THEN 系统应自动适配图片大小并更新页面
6. WHEN 图片网格加载 THEN 系统应显示加载状态
7. WHEN 没有可用图片 THEN 系统应显示"暂无图片"提示并提供上传按钮链接

### 需求 5：可编辑元素标识

**用户故事**：作为内容管理员，我想清楚地看到哪些内容可以编辑，以便知道可以修改哪些部分。

#### 验收标准

1. WHEN 页面进入编辑模式 THEN 系统应在所有可编辑元素上添加视觉标识
2. WHEN 鼠标悬停在可编辑元素 THEN 系统应显示蓝色边框和编辑图标
3. WHEN 元素被点击 THEN 系统应显示高亮状态
4. WHEN 显示编辑提示 THEN 系统应包含字段名称（如"hero.background.image"）
5. WHEN 元素是文字 THEN 系统应显示文字图标
6. WHEN 元素是图片 THEN 系统应显示图片图标

### 需求 6：编辑状态同步

**用户故事**：作为内容管理员，我想在保存修改后立即看到效果，以便确认修改是否正确。

#### 验收标准

1. WHEN 用户保存文字修改 THEN 系统应在预览页面实时更新文字内容
2. WHEN 用户保存图片修改 THEN 系统应在预览页面实时更新图片
3. WHEN 内容更新失败 THEN 系统应显示错误提示并保持原内容
4. WHEN 多个内容项被修改 THEN 系统应正确更新所有修改的内容
5. WHEN 用户切换语言 THEN 系统应显示对应语言的内容

### 需求 7：响应式预览

**用户故事**：作为内容管理员，我想在不同设备尺寸下预览页面，以便确保内容在各种设备上显示正常。

#### 验收标准

1. WHEN 预览模式打开 THEN 系统应提供设备尺寸切换选项（桌面、平板、手机）
2. WHEN 用户选择桌面模式 THEN 系统应以全宽显示预览
3. WHEN 用户选择平板模式 THEN 系统应以768px宽度显示预览
4. WHEN 用户选择手机模式 THEN 系统应以375px宽度显示预览
5. WHEN 切换设备尺寸 THEN 系统应保持编辑模式状态

### 需求 8：编辑权限和安全

**用户故事**：作为系统管理员，我想确保只有授权用户可以使用可视化编辑器，以便保护网站内容安全。

#### 验收标准

1. WHEN 未登录用户访问预览页面 THEN 系统应只显示预览不显示编辑功能
2. WHEN 已登录管理员访问预览页面 THEN 系统应显示"进入编辑模式"按钮
3. WHEN 用户尝试保存修改 THEN 系统应验证JWT token
4. WHEN token无效或过期 THEN 系统应拒绝保存并提示重新登录
5. WHEN 保存操作 THEN 系统应记录操作日志包含用户和时间

### 需求 9：编辑历史和撤销

**用户故事**：作为内容管理员，我想查看编辑历史并能撤销修改，以便在出错时恢复内容。

#### 验收标准

1. WHEN 用户保存修改 THEN 系统应自动创建内容版本
2. WHEN 用户点击"查看历史"按钮 THEN 系统应显示该内容项的所有历史版本
3. WHEN 用户选择历史版本 THEN 系统应显示该版本的内容预览
4. WHEN 用户点击"恢复此版本" THEN 系统应将内容恢复到选定版本
5. WHEN 恢复版本 THEN 系统应创建新版本记录恢复操作

### 需求 10：批量编辑模式

**用户故事**：作为内容管理员，我想一次性修改多个内容项，以便提高编辑效率。

#### 验收标准

1. WHEN 用户进入编辑模式 THEN 系统应提供"批量编辑"选项
2. WHEN 用户启用批量编辑 THEN 系统应允许选择多个元素
3. WHEN 用户选择多个元素 THEN 系统应显示已选择的元素数量
4. WHEN 用户点击"批量保存" THEN 系统应一次性保存所有修改
5. WHEN 批量保存完成 THEN 系统应显示成功数量和失败数量

## 技术约束

### 前端技术
- 使用iframe嵌入前端页面进行预览
- 使用postMessage进行iframe与父窗口通信
- 使用React Portal渲染编辑弹窗
- 使用CSS overlay实现编辑提示层

### 后端技术
- 复用现有的ContentController API
- 使用现有的JWT认证机制
- 使用现有的版本控制系统

### 安全要求
- 所有编辑操作需要JWT认证
- 验证用户权限
- 防止XSS攻击
- 记录所有编辑操作日志

## 用户体验要求

### 性能要求
- 预览页面加载时间 < 2秒
- 编辑弹窗打开时间 < 300ms
- 保存操作响应时间 < 1秒
- 预览刷新时间 < 1秒

### 可用性要求
- 编辑提示清晰易懂
- 操作流程简单直观
- 错误提示友好明确
- 支持键盘快捷键（Esc关闭弹窗，Ctrl+S保存）

### 兼容性要求
- 支持Chrome、Firefox、Safari、Edge最新版本
- 支持1920x1080及以上分辨率
- 支持触摸屏操作（平板）
